# eat-bot

Личный Telegram-бот для подготовки постов о еде по фотографиям продукта, этикетки и чека. Python 3.12+, GigaChat API, Tesseract OCR и SQLite. Публикация только после проверки владельцем и нажатия кнопки.

## Возможности

- Фото альбомом или отдельными сообщениями; первое становится главным. Остальные используются как источники и не публикуются.
- Извлечение названия, массы, производителя и стоимости. Уточнение важных нечитаемых данных и неоднозначных скидок.
- Кнопки «Собрать пост», «Опубликовать», «Исправить», «Выбрать главное фото», «Отменить».
- Правки обычным сообщением: «0 ₽», «измени массу на 150 г», «убери второй продукт».
- Черновики, фотографии, кэш распознавания и правки сохраняются при перезапуске.
- Доступ только одному владельцу; связывание через одноразовый код при установке.
- Long polling, без открытия входящих портов. Необязательный HTTP-прокси только для Telegram.
- Редактируемые правила оформления на основе eat. КБЖУ по умолчанию отключено. Хештеги перед названием; сохраняется валюта покупки и формат скидок.

## Требования

Ubuntu с Python 3.12+, systemd, Tesseract с языками `rus` и `eng`, отдельный токен Telegram-бота и действующий доступ к GigaChat API. Обычная учётная запись чата GigaChat сама по себе не подтверждает доступ к API.

Python-зависимости отсутствуют: используется стандартная библиотека. Распознавание выполняется по одному изображению, затем модель сопоставляет извлечения и OCR. Готовую подпись формирует код из структурированных данных, а не свободный ответ модели.

Распознавание может ошибаться в названиях, юрлицах, ценах и связях между товарами. Проверка черновика человеком обязательна. Общую скидку заказа нельзя автоматически считать скидкой конкретного товара без распределения или уточнения владельца.

## Проверка кода

Из каталога репозитория:

```bash
python3 -m unittest discover -s tests -v
```

Тесты работают с временной SQLite и подменённым Telegram-транспортом. Они проверяют сохранение материалов, доступ, правки, выбор фото, отмену, ограничения подписи, защиту от повторной отправки и работу HTTP-прокси. Они не подтверждают доступность внешних API на конкретном сервере.

## Установка

Перед установкой проверь ОС, доступную память и существующие службы. Не изменяй их настройки и не перезапускай ради бота. Входящих портов приложению не требуется.

1. Подготовь защищённый файл с ключом GigaChat непосредственно на сервере. Токены и ключи не помещай в репозиторий, командную строку или журналы.
2. При необходимости подготовь файл настроек с `TELEGRAM_PROXY_URL` (HTTP/HTTPS-прокси) и `GIGACHAT_CA_BUNDLE` (путь к доверенному CA). Установщик импортирует только эти два параметра; исходный файл не изменяет. Относительный путь к CA разрешается относительно этого файла.
3. Проверь код командой выше.
4. От root из каталога репозитория запусти `python3 deploy/setup.py`. Введи токен Telegram по скрытому запросу, укажи пути к файлам настроек и ключа. Пустой путь настроек означает отсутствие импорта.
5. Отправь команду с одноразовым кодом из консоли в личный чат бота. Затем создай отдельный тестовый канал, добавь бота администратором с правом публикации и сам отправь туда вторую команду с кодом.
6. Установщик создаст отдельного пользователя `eat-bot`, окружение `/opt/eat-bot/.venv`, настройки `/etc/eat-bot`, данные `/var/lib/eat-bot` и unit-файл. Служба ещё не запущена. Если произошла частичная ошибка, сначала выясни состояние, не повторяй установку вслепую.
7. Проверь unit-файл: `systemd-analyze verify /etc/systemd/system/eat-bot.service`.
8. После успешной проверки выполни `systemctl daemon-reload`, затем `systemctl enable --now eat-bot.service`. Это запускает только новую службу.
9. Проверь `systemctl is-active eat-bot.service`. Журнал только этой службы: `journalctl -u eat-bot.service -n 20 --no-pager`.

Установщик не изменяет nginx, firewall, VPN, другие службы или их файлы. Прокси Telegram использует отдельный HTTP opener для API и скачивания фото; глобальные сетевые настройки и подключение GigaChat этим не меняются. TLS-сертификаты проверяются.

## Проверка перед основным каналом

В тестовом канале проверь альбом и отдельные фото, сопоставление товара с чеком, скидку, правку до нулевой цены, смену массы и главного фото, удаление лишнего товара и отмену. Перезапусти только `eat-bot.service` с готовым черновиком: `/start` должен восстановить его. Дважды нажми «Опубликовать» и убедись, что пост один. Проверь отсутствие доступа с другого аккаунта и потребление ресурсов службы.

После проверки добавь бота администратором основного канала, запусти `python3 /opt/eat-bot/set_channel.py` и укажи `@username` или числовой ID канала. Скрипт проверяет право публикации и сохраняет назначение. Перезапусти только `eat-bot.service`. Автоматической отправки при смене канала нет.

## Работа и настройки

`/start` показывает текущий черновик; `/cancel` отменяет его. Подпись к присланной фотографии учитывается как указание владельца. Для нескольких продуктов явно называй товар, к которому относится правка.

Правила оформления: `/etc/eat-bot/post_rules.md`. Они читаются при каждой сборке. Изменения владельца к конкретному посту имеют приоритет. После изменения материалов или текста прежние кнопки публикации недействительны.

Лимит приложения: 20 изображений до 15 МБ каждое. Для мелких этикеток можно отправлять JPEG/PNG как файл. Во время распознавания новые сообщения ждут в очереди Telegram. При исчерпании API-лимита или ошибке материалы остаются в хранилище.

Подпись проверяется на лимит 1024 единиц UTF-16; слишком длинный текст нужно сократить. Публикуется одиночное фото с HTML-форматированием. Исходная цена зачёркивается средствами Telegram. callback_data укладывается в 64 байта.

Публикация защищена захватом состояния в SQLite. При обрыве связи результат `sendPhoto` может быть неизвестен: автоматический повтор запрещён, бот просит проверить канал. Разрешение новой попытки требует дополнительного подтверждения и нового нажатия «Опубликовать». Bot API не даёт ключ идемпотентности для `sendPhoto`, поэтому гарантировать exactly-once доставку при сетевом сбое нельзя.

## Данные и секреты

В репозитории нет фотографий, рабочих конфигураций, ключей и БД. Установщик создаёт секретные файлы с доступом `root:eat-bot 0640`, каталог настроек `0750`, каталог данных `0700`. Сервис работает непривилегированным пользователем с ограничениями памяти и CPU из unit-файла.

В `/var/lib/eat-bot` находятся БД, фотографии и кэш. Отмена черновика не удаляет файлы; сроки хранения и очистка пока ручные. Для резервной копии SQLite используй backup API, а не копирование открытой БД без WAL. Резервные копии также должны оставаться приватными.

Загруженные в GigaChat файлы удаляются после извлечения. Неудачные удаления записываются в локальную очередь и повторяются перед следующей сборкой. Сбой между успешной загрузкой и записью ID может оставить файл в удалённом хранилище — периодически проверяй его.
